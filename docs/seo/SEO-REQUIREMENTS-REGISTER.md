**R-06 404 and unknown-path metadata hygiene (finding X1).** Approval: batch authorized 2026-10-31. **Batch owner: the SEO foundation batch (this PR). Not part of R-10.** Owner: Site. Evidence: **READY FOR QA, after a first correction.** Production before: `/foo/bar` returned a real 404 with noindex yet emitted a canonical, three hreflang links and og:url naming itself [V 2026-10-31]. The first head of this PR (`94b0b75`) still did the same on `/products/x/y`, `/collections/x/y`, `/categories/x/y`, `/blog/x/y`, `/legal/missing` and `/legal/missing/deeper`, because it accepted every descendant of a public family (independent QA reproduced it). Fix: `<SeoLinks />` now describes a path only when it has the **exact shape of a real page route** (`routeShapeOf`/`seoLinkPlan`, `lib/seo-policy.ts`; the table is compared with the `page.tsx` files under `app/` by a unit test). The shared locale-family rules in `lib/locale.ts` are untouched, so routing and navigation are unchanged. **Covered by rendered checks (`FOUNDATION` rows):** unknown single-, two- and three-segment paths; malformed children and deeper descendants of every public family (products, collections, categories, blog, legal, jewelry-guide, shopping-guide, faq, about, loyalty, sale, wholesale, layaway) and family roots that are not pages (`/legal`, `/categories`); malformed children of private routes (`/cart/…`, `/search/…`, `/login/…`, `/account/…`, `/checkout/…`); `/en` and `/ja` forms of the main malformed shapes; missing resources (one real shape, nothing behind it) bare and localized; a language the sitemap does not list; `/ja/layaway`; `/en/cart`; an invalid locale. Known valid templates must return HTTP 200 in both languages. **Not covered:** every possible URL; signed-in pages; real-Hub data (the develop-preview gate in `SEO-QA-REPORT.md` §15 covers it). **Second class found while correcting (2026-10-31): the live DOM, not the raw HTML.** In a real browser a **missing resource with a real route shape** (a product, collection or category slug that does not exist) showed a canonical, three hreflang links and (bare form) og:url in the DOM although its raw HTML had none; `develop` does the same, and the first corrected head added og:url to the locale form. Search engines that run JavaScript read the DOM. Fixed by two rules: a locale page whose own metadata function returns no title (the resource does not exist) describes nothing (`localizedMeta`), and a bare dynamic public URL describes nothing while the legacy redirects are on (it only ever 404s or 307s; with `SEO_LEGACY_REDIRECTS=off` the rollback keeps its tags). The new `scripts/check-seo-dom.mjs` checks the live DOM in desktop and phone browser contexts for valid templates, every 404 shape, the 404 page's real UI, client-side navigation, and every console or page error. Both checkers (`check-seo-live.mjs` raw HTML, `check-seo-dom.mjs` live DOM) share one route matrix (`FOUNDATION_MATRIX` in `scripts/lib/seo-check-core.mjs`; a unit test enforces parity of their coverage keys and forbids private copies), fail closed (the sitemap is validated, malformed XML included; expected template families and both eligible languages are required; unavailable siblings and their hreflang exclusion are tested explicitly; an inventory of expected, checked, missing and skipped coverage is printed), separate the request origin from the public origin (`SEO_CHECK_PUBLIC_ORIGIN`), and use a preview credential only for the one exact origin named in `SEO_CHECK_BYPASS_ORIGIN`: the raw checker as a header pinned to that origin with no redirect followed, the browser as Vercel's bypass cookie obtained once by Node and scoped to that host by the browser's own rule (every port of the host receives it, no subdomain and no parent domain does; the browser never sees the secret; no request interception; native redirect semantics preserved and each scope claim proved by `scripts/test-seo-check-isolation.mjs`). Every printed line is redacted of every accepted credential before any truncation; credentials shorter than 8 characters are refused before use; failure paths (timeout, dropped connection, reflected secret, truncation boundary) are tested. The sitemap must be balanced XML (closed and correctly nested elements, well-formed attributes) with valid extensions preserved. Intentional checker differences are stated in the matrix's comment (gated descendants: 307 Location vs final URL; 404 page UI: DOM only; 2E-1 redirects and robots.txt: raw only). Gap: none known; production confirmation after release. Acceptance: each covered shape is a real 404 with noindex and no canonical, hreflang or og:url in both the raw HTML and the live DOM, and every valid route keeps its output. Next: QA, then release.
