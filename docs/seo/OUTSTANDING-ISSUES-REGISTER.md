## 5. OG-PRODUCT — product-page sharing metadata
- **Current status:** CLOSED — DEPLOYED AND VERIFIED LIVE (2026-10-30). Released through PR #442 (`develop` → `main`, merge commit `95189746d18ef97a17b5d98dbe2c8a952330ddc0`; Vercel production deployment `7416880444` Ready); the code is PR #441 (`c4791fd`). On production, all 12 baseline product URLs (6 products × English and Japanese) pass every check and the 12 non-product sample pages are unchanged. History: "AUDITED; QA PENDING" → "CONFIRMED PRODUCTION METADATA DEFECT — CODE FIX REQUIRED" (PR #440) → "IMPLEMENTED — PRODUCTION VERIFICATION PENDING" (PR #441) → closed. Evidence: `docs/seo/SEO-QA-REPORT.md` §13 and §14.
- **Implemented correction (PR #441):** `lib/product-seo.ts` `productOpenGraph()` restates `type: "website"`, `siteName: "Cha Jewels"`, `locale` / `alternateLocale`, `og:url` (the canonical, built by the same `localeAlternates` function that writes it), and the product's own primary photo with the product name as alt; the no-photo fallback names the brand image (`/opengraph-image.png`, 1200×630, alt "Cha Jewels"). `app/products/[slug]/page.tsx` calls it. Title, description, Twitter, canonical, hreflang and JSON-LD are unchanged. Evidence and tests: `docs/seo/SEO-QA-REPORT.md` §13.
- **Original record, kept (the defect as it stood before PR #441):**
- **Repository / workstream:** website, `app/products/[slug]/page.tsx` `generateMetadata`.
- **Root cause (code, observed):** `openGraph: img ? { images: [img.url] } : undefined`. A page-level `openGraph` object replaces the inherited site-wide one (the same mechanism fixed for collection and category pages in Step 2 with a conditional spread; product pages were not touched).
- **Evidence:**
  - **Owner-provided audit evidence (not an exhaustive crawl):** 453 products appear in English and Japanese, giving 906 product URLs in the reported sitemap (906 is the sitemap count, not a crawl). Twenty-one sampled live product pages consistently lacked the relevant OpenGraph fields. Product pages share one metadata generator.
  - **Observed by Claude (production, 2026-10-29, product R2715, EN and JA):** product-specific `og:title`, `og:description` and `og:image` and the Twitter title, description, card and image are present; `og:site_name`, `og:type`, `og:locale`, `og:locale:alternate` and `og:url` are absent, as are image alt and size.
- **What is wrong:** the product's own title, description and image survive, but the site-wide fields (site name, page type, language and alternate language) and `og:url` are missing from every sampled product page.
- **Required fix (implemented in PR #441, released through PR #442 and verified live):**
  - preserve each product's title, description and authentic product image;
  - restore the site name, an appropriate OpenGraph page type, and the language and alternate-language fields;
  - verify `og:url`;
  - keep canonical and hreflang unchanged;
  - keep the existing Twitter sharing metadata;
  - add automated regression coverage.
  - Design points, resolved in PR #441: the type is `website` (the installed Next 15.5.25 OpenGraph types, `opengraph-types.d.ts`, have no product type — previously marked UNVERIFIED, now checked), and `og:url` equals the locale canonical.
- **No-photo edge case (not a confirmed defect):** no active product without a photo was observed, so this is not classed as a production defect. The same code path would emit no `openGraph` at all for such a product. **Expected behaviour (implemented in PR #441; covered by simulated tests only, because no real product without a photo has been observed):** the page keeps its title and description, keeps the full site-wide OpenGraph fields, and uses the site brand image as the share image (the existing fallback used by collection and category pages), never an empty or broken image. The regression tests include a simulated product without a photo.
- **Facebook and Messenger (checked at closure):** the Facebook Sharing Debugger was run on the live English and Japanese R2715 pages and showed correct previews (product photo, title, description, canonical URL), with one advisory warning, `fb:app_id` missing (see the observation below). A Messenger preview was **not tested** (it would require sending a message). The debugger is additional to the HTML checks; it was not a prerequisite for classifying or closing the issue.
- **Owner approval (historical; met):** the code correction (PR #441) was reviewed and released at the owner's direction (PRs #441 and #442); it adds no tag beyond the fields listed above and makes no claim about origin, quality, certification or availability.
- **Definition of done (met 2026-10-30):** the focused code correction is approved, merged, deployed and verified against actual English and Japanese product pages, with automated tests (including the simulated no-photo product) and live metadata evidence showing the title, description, image, site name, type, locale pair and `og:url`, with canonical, hreflang, Twitter metadata, and the `Product` and `BreadcrumbList` schema unchanged.
